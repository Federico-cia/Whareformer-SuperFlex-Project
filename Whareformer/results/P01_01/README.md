# Whareformer baseline — EPIC-KITCHENS `P01_01`

## Purpose and status

This folder records an **inference run** of pretrained Whareformer on video `P01_01`, and the subsequent exact-ID association between Whareformer tracks and the `compare200` object geometry package. **No model training or fine-tuning was performed** in this run. The video is selected through the configuration's `train` split; these are **not held-out test-set** results.

## Code and checkpoint provenance

- Base Whareformer repository commit (`git rev-parse HEAD`): `82dd349957e1f04f92a2979b4c92c2f3fed445c5`.
- Inference checkpoint: `checkpoints/whareformer.pt`.
- Checkpoint SHA-256: `5b2e6692461f837ec662d0ac75a5f8c08e4fa9778e5c1b9833598cf90a58ee1d`.
- Checkpoint itself is **not** included here. To reproduce results exactly, obtain a checkpoint with the SHA-256 above.
- The base commit **does not fully describe the executed code**: the following local Windows adaptations to `src/utils/launcher.py` were in effect:
  1. `import psutil` added.
  2. Available RAM calculation changed from Unix-only `os.sysconf('SC_PAGE_SIZE') * os.sysconf('SC_PHYS_PAGES') / (1024. ** 3)` to `psutil.virtual_memory().total / (1024. ** 3)`.
  3. Per-process memory budget reduced from `64` GB to `4` GB (`mem_per_proc = 4`).
- Keep an exact patch of these local changes in this shared repository as `launcher_windows.patch`, generated by `git diff -- src/utils/launcher.py` from the original Whareformer checkout (see below).
- `data/epic_osnom/EPIC_100_video_info.csv` showed **no content changes** in `git diff --stat`, only a Windows LF/CRLF line-ending warning. It is not necessary to copy this CSV into GitHub solely for that warning.

## Configuration

The file `whareformer_config.yaml` in this folder is the effective configuration supplied for this run, including:

- `tracking.split: train`
- Only `P01_01` enabled in `videos.train`
- `tracking.gpu_accelerate: false` (CPU)
- `tracking.matcher_type: whareformer`
- `tracking.pca_dim: 256`
- `tracking.matcher_params.model_path: checkpoints/whareformer.pt`
- Output directory `outputs/epic/whareformer`

## Run commands

Run from the **root of the original Whareformer repository**, with the correct environment activated and its pre-extracted `P01_01` observations in place:

```cmd
set PYTHONPATH=%CD%\src
python src/scripts/run_tracker.py --config src/config/epic/whareformer_config.yaml
python build_tracks_by_id.py --video P01_01
python link_compare200_tracks.py --video P01_01 --compare-dir ..\compare200
```

The last command expects the extracted `compare200` package to be a sibling of the original Whareformer directory and to contain `observations_for_tracking.json`. Helper scripts `build_tracks_by_id.py` and `link_compare200_tracks.py` are project additions; preserve their exact versions alongside the shared project source.

To archive the exact executed `launcher.py` modifications, from the original Whareformer root run:

```cmd
git diff -- src/utils/launcher.py > launcher_windows.patch
```

Then copy `launcher_windows.patch` to the shared repository under `Whareformer/results/P01_01/`.

## Artifacts

- `tracks_by_id.json`: Whareformer predicted tracks, regrouped by ID from `tracking_outputs.pkl` and `object_annotations.json`. Track IDs are predictions, **not ground-truth object identities**.
- `compare200_joined_observations.json`: exact associations from the `compare200` observation manifest to Whareformer track IDs, with **relative** file paths into the extracted `compare200` package. This file does **not** embed point-cloud arrays or images.
- `track_match_report.json`: annotation-to-tracker join report: 110,590 exact matched rows, 0 unmatched; 52 predicted tracks.
- `compare200_join_report.json`: 71 of 73 geometry observations matched exactly; 2 unmatched. 18 tracks include matched geometry, of which 9 have at least two observations.
- `compare200_track_candidates.csv`: geometry-observation counts for candidate tracks. Track `9` (category `pan`) has 18 matched observations. Its apparent identity was checked visually, but visual plausibility does not prove geometric alignment.
- `results.csv`: Whareformer evaluation output from the run (145 rows). Columns: `n`, `r=0.3_pcl`, `r=0.3_correct`, and `r=0.3_total`. Observed `r=0.3_pcl = 100 * correct / total`. This file should **not** be described as held-out benchmark accuracy without checking the evaluation protocol and what `PCL` measures.

## Important limitations

- The 40 frames sampled per video in `compare200` are temporally sparse. A matched track is not proof that an object's observed point clouds are mutually registered, nor that the 3D depth scales agree.
- `launcher.py` changed the process memory budget for local execution; results should be reproduced using the supplied effective configuration and exact checkpoint, and any discrepancies investigated.
- For a proper 3D reconstruction study, validate same-object identity and point-cloud registration, and evaluate the geometry on withheld views instead of reusing the same input views as reference.
